================================================================================
                    BUILD ERROR FIX - AUTHENTICATION CONTEXT
================================================================================

PROBLEM:
  Error: useAuth must be used within AuthProvider
  Failed page: /settings (and all other protected pages)
  Build error: Static export cannot pre-render pages that require AuthProvider

ROOT CAUSE:
  During static export (pre-rendering at build time), Next.js tried to render
  all pages including protected pages wrapped with ProtectedRoute component.
  
  The ProtectedRoute component uses the useAuth() hook which requires the
  AuthProvider context to be available. But AuthProvider only exists at
  runtime (client-side), not at build time.

SOLUTION:
  Added "export const dynamic = 'force-dynamic'" to all protected pages.
  This tells Next.js to skip pre-rendering these pages and instead render
  them on-demand on the server when users request them. This is the correct
  approach for authentication-protected pages.

================================================================================
                       WHAT 'force-dynamic' MEANS
================================================================================

export const dynamic = 'force-dynamic'

This Next.js configuration tells the framework:
  • DO NOT pre-render this page at build time
  • DO render this page on-demand when users request it
  • DO make API calls and access context on the server
  • DO provide full access to authentication context

This is the recommended approach for:
  ✓ Protected/authenticated routes
  ✓ Pages that check user permissions
  ✓ Pages with personalized content
  ✓ Pages using hooks that require context

================================================================================
                       HOW THIS WORKS IN PRODUCTION
================================================================================

STATIC PAGES (Pre-rendered):
  • Generated once at build time
  • Served as static HTML/CSS/JS files
  • Ultra-fast delivery (no server computation)
  • Perfect for: home page, about page, contact page, etc.

DYNAMIC PAGES (On-demand):
  • Rendered when user requests them
  • Server-side rendering with access to AuthProvider
  • User authentication checked on the server
  • API calls made with proper authorization
  • Perfect for: protected/authenticated routes

CAPACITOR ANDROID:
  • Static pages bundled in APK
  • Dynamic pages rendered by Node.js server
  • Requires: Backend server running (Node.js/Vercel)
  • Alternative: Deploy to Vercel (handles both automatically)
